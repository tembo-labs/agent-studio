# Backlog — Unscheduled

Stories that are designed but not on any phase milestone. Each entry
should explain enough that we can size and schedule it into a numbered
phase later without going back to first principles.

When something here graduates to a real phase, move the entry into
that phase's `USER_STORIES.md` and remove (or stub out) the row here.
Conversely, when a phase is in flight and scope-cuts happen, the
cut story usually lands here — keep the "moved from v0.X" provenance
line so future readers see the trajectory.

See [`USER_STORIES.md`](./USER_STORIES.md) for the full set.

## What goes here vs. an in-phase Deferred section

- **In-phase `Stretch (Considered, Deferred)`** — stories that were
  intentionally out of scope for that phase from the start. They
  inform the phase's intent but don't represent active backlog.
- **`context/backlog/` (this folder)** — stories that *don't have a
  phase yet*. Either originally planned and cut, or surfaced
  mid-development without a natural home. Move into a phase when
  it gets sized and scheduled.
